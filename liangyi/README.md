# 两仪行 · 十二元辰

一个基于 Phaser 的国风横版平台动作小游戏。玩家化身汉服巡界使，往返天庭与地府，收集每章的 5 枚元辰灵印，挑战十二生肖元辰，将掉落的生肖符文装入阴阳六道，组合自己的武器与术法，重整两界星序。原项目目录 `shadow-jump` 已更名为 `liangyi`；旧链接若失效，请访问 `liangyi/` 下的页面。

阳面采用青玉白衣，阴面采用玄衣朱绶。武器槽为空时，阳面使用御剑远攻，阴面使用镇魂近斩；装备生肖符文后可改变武器、攻击节奏和其他能力。沿途生灵包括云中纸鹤傀、提灯阴差、持盾天兵与冥火狐妖。

## 本地运行

在仓库根目录运行静态文件服务器：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

在浏览器打开 `http://127.0.0.1:8000/liangyi/`。项目无需构建或安装 npm 依赖；Phaser 4.2.0 随项目放在 `vendor/` 目录中，由当前站点加载，无需访问第三方 CDN。下载完整仓库后，可通过本地服务器离线运行；首次访问 GitHub Pages 仍需要网络。

部署时请完整发布 `liangyi/`，包括 HTML、样式表、`vendor/`、`src/` 和 `assets/` 目录。如果提示游戏引擎文件未能加载，请检查 `vendor/phaser.min.js` 是否已发布，并在 GitHub Pages 部署完成后刷新页面。

独立图鉴位于 `http://127.0.0.1:8000/liangyi/art-preview.html`，可比较双形态主角的实机尺寸与放大细节，切换待机、奔跑、起跳、下落、攻击、冲刺、受伤、换形八种动作，并查看四类小怪和十二生肖动态立绘。图鉴支持暂停动画细看，与游戏共用绘制代码。

## 六道轮回装备

正式游戏中按 `E` 或点击“六道装备”打开六边形轮回盘。正面为阳、背面为阴，各有六个道位，共十二槽。点击中央太极翻面，选择道位与生肖符文，点击“放入此道”或“卸下”编辑草案，再点击“确认装备”应用两侧配装。翻看另一面不会切换实际战斗配装；战斗中用 `L` 切换。

| 道位 | 装备作用 |
| --- | --- |
| 阿修罗道 | `J` 主武器，改变攻击方式、距离与节奏 |
| 天道 | `U` 主动术法，改变灵耗、冷却与攻击效果 |
| 人间道 | 身法，调整移动、跳跃、冲刺等能力 |
| 畜生道 | 灵契，召唤随行生肖灵体协击 |
| 饿鬼道 | 回灵，按对应的战斗条件恢复灵力 |
| 地狱道 | 攻击附效，附加侵蚀、追猎等效果 |

正式历练击败 Boss 后立即获得一枚对应符文，无需等到进入界门。同种生肖最多持有两枚，之后每次正式击败转为 10 符墨；符墨目前只累计，没有消费入口。每面同种生肖最多装备一枚，两面同时装备需要持有两枚。移动、替换和卸下都不消耗符文，空槽恢复基础能力。

开局准备、附近没有敌人的起点或已点亮长明灯、击败元辰后及章节结算时可以确认装备。正式战斗中打开装备页会暂停游戏，可编辑草案，回到安全处再确认。关闭面板后草案在本次页面会话中保留，“还原草案”可恢复已确认的配装；刷新仅恢复已确认的正式装备。换装和切面均不补充生命、灵力或重置冷却。

想先体验全部符文，可进入“演武 · 直面元辰”，每种临时提供两枚，允许试装与实战。演武不发放永久符文或符墨，返回正式历练恢复正式库存与配装。

当前运行时首版的效果与数值以正式装备页说明为准。设计资料集中在 [docs/](docs/README.md)：[系统设计](docs/reincarnation-runes-design.md)、[十二生肖效果目录](docs/reincarnation-runes-catalog.md) 与 [JSON 数据](docs/reincarnation-runes-catalog.json)。完整目录中的 24 种武器与 144 条复杂道位机制仍是设计目标，部分身法、灵契等采用首版简化实现。可命名预设、训练木桩等也尚未实现。

[独立设计试装页](runes-preview.html)保留完整提案说明和三个示范配装，使用自己的预览库存与浏览器记录，不会向正式游戏写入符文或装备。

## 操作

| 操作 | 键位 |
| --- | --- |
| 左右移动 | `A` / `D` 或左右方向键 |
| 跳跃，空中可再跳一次 | `K`，轻点低跳、按住高跳 |
| 攻击 | `J`，普通武器按住连攻；蓄力武器按住蓄力、松手释放，详见装备说明 |
| 当前面天道术法 | `U` |
| 打开六道装备 | `E` |
| 切换所在世界 | 空格 |
| 切换阴阳六道配装 | `L`，切换间隔 0.6 秒 |
| 沿当前朝向冲刺 | `Shift` |
| 暂停或继续 | `P` 或 `Esc` |
| 关闭操作指南 | `Esc` |
| 从头重新开始 | `R` |

触屏使用下方的方向、跳跃、攻击、技能与切换按钮；横屏可获得更大的游戏画面。顶部按钮也可以打开装备、切换世界和阴阳配装、查看指南、开关声音、调低动态效果，以及切换界面风格（青玉 / 玄墨 / 赤霞）。

所在世界决定可落脚的平台、可见灵印和敌人；阴阳配装决定当前生效的六道能力，两者可独立切换。灵力基础自然恢复为每秒 4 点，天庭配阳面、地府配阴面时额外恢复每秒 2 点。异界配装不会持续扣灵力，也不会在零灵力时被强制切回；术法仍需足够灵力才能释放。

## 十二元辰与章节

顶部元辰星盘可直接选择任意章节。每章需要集齐 5 枚灵印、击败当值元辰，再进入右侧两界门，才会记录正式通关。Boss 的半血觉醒会改变招式和受击弱点；对应弱点极性造成完整伤害，另一极性造成 45% 伤害。按 `L` 切换阴阳配装可应对弱点，近战或远程不决定极性。攻击保留出手时的极性，飞行途中切面不会改变已发出攻击。

| 元辰 | 章节 | 初始世界 | 初试 → 半血觉醒 |
| --- | --- | --- | --- |
| 子鼠 · 掌灯使 | 子夜渡口 | 地府 | 锁魂符 → 散灵扇 |
| 丑牛 · 镇岳君 | 镇岳天门 | 天庭 | 冲阵 → 符雨 |
| 寅虎 · 破军将 | 伏虎幽谷 | 地府 | 飞扑 → 散灵扇 |
| 卯兔 · 望舒仙 | 月桂仙台 | 天庭 | 符雨 → 锁魂符 |
| 辰龙 · 沧溟帝 | 沧溟龙渊 | 地府 | 回旋灵流 → 符雨 |
| 巳蛇 · 青绫仙 | 青绫仙苑 | 天庭 | 散灵扇 → 回旋灵流 |
| 午马 · 烈曜君 | 赤焰古道 | 地府 | 冲阵 → 散灵扇 |
| 未羊 · 祈岁翁 | 祈岁云庭 | 天庭 | 符雨 → 回旋灵流 |
| 申猴 · 灵霄客 | 灵猿幽阶 | 地府 | 飞扑 → 锁魂符 |
| 酉鸡 · 司晨官 | 丹霞晓台 | 天庭 | 散灵扇 → 符雨 |
| 戌犬 · 守夜神 | 守夜冥关 | 地府 | 锁魂符 → 冲阵 |
| 亥猪 · 玄坛尊 | 归元玄坛 | 天庭 | 冲阵 → 回旋灵流 |

六类招式均有出招预警：锁魂符瞄准蓄力时的位置；散灵扇发射扇形飞符；冲阵横穿元辰坛；符雨落在三处地面标记；飞扑跃向标记位置并在落地后产生双向冲击；回旋灵流向四周释放灵弹。根据标记移步、起跳或寻找弹幕空隙。

当前十二章共用一套基本路线，采用三种平台高度节奏，并按章节变化初始世界、平台与灵印所在世界、小怪血量和巡逻速度。各章配置自己的生肖形象、名称、数值及两阶段招式组合。Boss 战场为两界共用的连续地面。

“演武 · 直面元辰”会直接进入当前章的 Boss 战场，免去沿途灵印收集和小怪，并提供全部生肖符文用于临时试装。演武通过后可返回本章历练；演武结果不计入正式通关、十二元辰归位或永久符文记录。

## 检查点与保存

落地经过长明灯检查点会保存本次复活位置，首次激活恢复部分生命和全部灵力。死亡后可从已点亮的长明灯继续，保留本次收集的灵印、角色成长及战斗进度。`R`、“重新出发”或选择章节会重新开始对应关卡，重置本次探索状态。

正式通关后，已归位的生肖编号保存在当前浏览器、当前站点的 `localStorage` 中，键名为 `liangyi-zodiac-progress-v1`；刷新后可在星盘查看，并再次挑战任意章节。本局位置、生命、灵印和检查点状态只保留在当前运行中，刷新页面会从第一章重新开始。声音、动态效果与界面风格偏好另存于 `liangyi-preferences`。

符文库存、符墨、已确认的阴阳配装和奖励领取记录独立保存在 `liangyi-runes-v1`。首次创建符文存档时，旧通关记录中已归位的生肖各补发一枚，之后不重复补发。每次正式关卡实例的 Boss 只发一次奖励；死亡续关保留领取状态，重新出发或重新选章会建立新实例，可再次挑战获取符文。

切换浏览器、端口或站点地址会使用对应的本地存储；清除站点数据会清除这些记录。符文存档损坏时先备份原值，再重建存档；无法读取或备份时不覆盖原数据。存储不可用或写入失败时，装备页会提示本次仅会话有效，此时新增符文与配装无法保证刷新后保留。

## 源码与验证

- `src/game-scene.js`：输入、物理、战斗、关卡进度和界面联动。
- `src/rune-store.js`：符文库存、正式掉落、配装保存、旧记录迁移和演武临时库存。
- `src/rune-combat.js`：符文武器、术法与道位效果；正式装备页说明与运行规则共用数据。
- `src/rune-ui.js`、`rune-ui.css`：正式六边形双面装备盘、库存、草案与安全换装交互。
- `src/data/zodiac.js`：十二生肖的名称、章节、初始世界、生命、招式、预警和背景文案。
- `src/data/level-01.js`：基本路线、灵印、敌人、检查点，以及生成十二章变体的配置函数。
- `src/art.js`、`src/enemy-art.js`、`src/zodiac-art.js`、`src/world-art.js`：汉服主角、四类小怪、十二生肖与两界场景的绘制和动画，详见 [美术说明](assets/README.md)。
- `art-preview.html`：独立的两界生灵图鉴。
- `runes-preview.html`：可独立部署的六边形双面装备设计预览，包含页面运行所需资源。
- `docs/`：六道轮回系统规则与十二生肖效果设计资料。
- `index.html`、`styles.css`：菜单、HUD、操作指南与触控布局。
- `vendor/`：随站点托管的 Phaser 引擎与许可证。

在仓库根目录使用 Node.js 18 或更高版本运行逻辑回归测试：

```sh
node --test liangyi/tests/*.test.cjs
```

逻辑回归测试包含跳跃容错、冲刺、暂停、投射物寿命、检查点、重开、世界切换碰撞、启动依赖提示，以及符文库存、掉落去重、保存失败、演武隔离和装备面板的场景联动。测试使用模拟场景，渲染、音效、触控多指操作和完整路线可玩性仍需浏览器验证。

浏览器验收可按以下步骤进行；此清单是验证方法，不表示十二章完整流程均已逐一实测：

1. 打开图鉴，切换八种动作并暂停，检查双形态主角、四类小怪及十二生肖的绘制、动画和裁切。
2. 从第一章开始，验证轻重跳、二段跳、冲刺、两界平台切换，以及同界和异界配装的灵力恢复；零灵力时确认不会自动切面，并沿路线收齐 5 枚灵印。
3. 点亮长明灯后死亡续关，确认灵印和战斗进度保留；重新出发后确认本次状态重置。
4. 用星盘依次进入十二位元辰的演武，检查六类招式的预警、半血换招和极性弱点。按 `E` 用临时符文试装、按 `L` 切面实战；返回历练后确认正式库存、配装及归位数量保留原值。
5. 在正式历练中击败 Boss，确认进入界门前已获得对应符文；刷新确认库存保留。继续验证第二枚符文、后续 10 符墨转换，以及死亡续关不重复领奖。
6. 用正式库存验证翻面、同侧移位、卸下、两侧数量限制及确认保存。战斗中只能编辑草案，安全处可确认；换装和切面不补血、不回灵、不刷新冷却。
7. 完成“灵印齐全、击败 Boss、进入界门”流程，检查下一章入口、星盘归位标记和刷新后的记录；分别检查三种高度路线与天庭、地府初始章的前进和回访路径。
8. 使用窄屏和触屏检查装备槽与确认按钮可达性、面板焦点、蓄力松手、多指移动与跳跃，以及关闭装备页后的暂停状态恢复。
